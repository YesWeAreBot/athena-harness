## 1. 调研核心结论

### "重建 vs append-only"是伪二分

正确分层：

```
durable record      —— 顺序追加，是事实与审计的载体
       ↓ 每次请求投影
model context       —— 每次请求重新物化，是注意力预算的载体
       ↓ 阈值触发
bounded compaction  —— 刻意的批量事件，产生新的检查点
```

三个参考实现都同时具备追加（持久化层）与重建（投影层）。

### 其他被纠正的二元框架

| 二元表述                        | 纠正                                                                     |
| ------------------------------- | ------------------------------------------------------------------------ |
| memory 或 chat history          | 两层并存：history 是事件记录，memory 是经筛选的派生状态                  |
| 工具结果全保留 或 全清除        | 必须分级：原始大输出、派生事实、错误/回执、可重放引用                    |
| 缓存命中 或 状态新鲜            | 两者不冲突也不互相保证                                                   |
| 对话型 AI 与功能性 agent 的二分 | 至少五个独立维度：持久性、投影策略、场景作用域、工具密度、状态新鲜度要求 |

## 2. 参考实现纠正要点

### MaiBot

- 主请求是结构化消息数组，不是单条模板 prompt
- Planner 与 Replyer 是两个独立 LLM 阶段，刻意用不同人格投影
- Replyer 默认过滤掉引用/工具结果/中期记忆
- 裁剪按消息条数 + 工具轮闭合，不是截断字符串

### YesImBot v3

- L1 没有 LLM 压缩，只是删除旧的 Agent 思考/动作/观察
- L2 是 embedding 检索（非压缩），只在窗口达 ~80% 且有新消息时触发
- L3 每日日记默认关闭
- Agent 工作记忆被渲染成 XML 嵌在 user message 里，丢失了原生工具语义

### YesImBot v4

- 每个模型边界都重新物化请求（读存储→条目变换→消息变换→模型消息）
- 存在清空、归档、切换；compaction 后可能只带压缩种子
- 追加前有钩子可改写待持久化条目
- 失败 turn 保留部分历史且不做自动重试关联

## 3. 成本分析摘要

### 关键结论

- 本方案（每 turn 重建帧）对 TTL 不敏感，成本取决于"状态有多大"（可工程控制），而非"用户多久说一次话"
- append-only 在历史涨到接近上下文窗口之前，纯 token 单价不输全量重建
- 支持重建的理由不是省钱，是三件非价格因素：冷启动方差、质量退化、状态正确性
- 游戏场景的高成本来自 tick 频率，不是布局

### 缓存经济学

- 缓存写入阈值：`h > write / (in − read)`，h 为期望命中次数
  - Opus/Terra ≈ 1.39、Gemini ≈ 1.11、DeepSeek = 0
- turn 内增量只在"剩余 step 期望 ≥ 2"时才值得请求缓存（Anthropic/Terra 上）
- 跨 turn 缓存命中取决于 provider TTL，不可控

### 大致量级（日常对话，120 turn/天，Opus）

| 方案        | warm     | cold     | 方差 |
| ----------- | -------- | -------- | ---- |
| append-only | ~$5/天   | ~$32/天  | 6×   |
| 本方案      | ~$3–4/天 | ~$5–6/天 | 1.4× |

这些是估算，不是实测。假设和前提见原始讨论。

## 6. 当时讨论中明确排除的做法

| 做法                         | 排除理由                                |
| ---------------------------- | --------------------------------------- |
| 滑动窗口（每轮挤掉最老一条） | 帧头每轮变化→前缀从第一条历史起全部作废 |
| 由模型自行判断工具是否失败   | 失败是机械可判定的事实，不需要语义判断  |
| 工具结果全保留               | 成本 + context rot                      |
| 工具结果全清除               | 失败原因丢失→重复犯错                   |
| 把压缩条目放在帧里           | 跟着帧变动→无法命中缓存                 |
| 每 turn 做小幅压缩           | = 滑动窗口的变体                        |
