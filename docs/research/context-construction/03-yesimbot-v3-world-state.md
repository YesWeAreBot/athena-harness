# YesImBot-v3 WorldState / Context Construction 证据报告（Athena §A + §B）

> **范围**：只检查 `/home/workspace/references/YesImBot-v3/packages/core/src/services/worldstate`、`packages/core/resources/templates` 及直接连接的 Agent/Prompt/Memory/Tool call sites。
>
> **证据标记**：`[实现]` = 当前代码直接可见；`[文档]` = README/演进笔记/任务 brief 的描述；`[代码推断]` = 由当前实现推导出的行为或风险；`[不可验证]` = 代码中没有 provider 级证据，不能当作事实。
>
> **一句话总结**：**YesImBot-v3 确实在每次 heartbeat 重新从 DB/JSONL/embedding 检索构造 `WorldState`，但它不是“稳定 system prompt + 快照”或“滚动裁剪 + LLM 压缩”的完整实现：实际请求是每次重渲染的动态 `system` + 包含快照的 `user` 两条消息，L1 只按事件上限和旧 Agent turn 做代码级删除，L2 只做 embedding/纯代码邻居合并，只有可选的 L3 每日日记调用 chat-model。**

## §A 调研发现

### A1. 实际 data-flow：每个 heartbeat 都会重建，而不是 append-only request replay

**结论先行：** 当前 v3 的请求链路是“持久化事件 → 重新投影快照 → 模板渲染 → 两条消息”，没有可复用的 request-scoped snapshot cache，也没有把上一次请求的 `assistant/tool` 原生消息列表传给模型。

**关键实现纠正：** `WorldState.self`、`WorldState.current_time` 在结构中存在，但默认 `world_state.mustache` 没有对应占位符（只渲染 channel/users/working_memory/L2/L3）；因此“snapshot 含 self/current time 并被模型看到”不能从当前默认模板成立 (`types.ts:247-260`; `world_state.mustache:20-109`)。

#### A6.2 Cache-prefix 结论

1. **代码没有实现 prompt cache。** `ChatModel` 只是把 `ChatRequestOptions` 合并后交给 xsAI `generateText/streamText`；没有 `cache_control`、breakpoint、prefix-id、previous-message reuse 或 hit/miss telemetry (`chat-model.ts:107-132,154-172`)。[实现]
2. **可推测的稳定前缀**是 system message 中未变的 persona/instructions；但同一 system message 后面仍有 `MEMORY_BLOCKS` 与 `TOOL_DEFINITION`，它们变化会让 provider 侧 message prefix 是否命中变得 provider-dependent (`memgpt_v2_chat.txt:103-138`; `_prepareLlmRequest`:88-92)。[代码推断]

4. **不能把任务 brief 给出的 Anthropic/OpenAI/Gemini 等 TTL/价格当作本仓库事实。** provider cache TTL、write/read 计费和实际命中率需另查官方模型文档与真实 `usage`；当前代码没有记录这些字段。[不可验证]

### B3 可直接给 Athena 设计讨论使用的“当前 v3 不应照抄”清单

1. **不要把 `WorldState` interface 的字段等同于模型实际可见字段**：`self` 和 `current_time` 定义了但默认 template 不渲染；trigger section 还有 object-vs-`.length` 风险 (`types.ts:247-260`; `world_state.mustache:1-20`)。
2. **不要把 `maxMessages` 当作 message-only rolling window**：最终是混合 events cap，且每个底层来源先各读 limit，再合并后截尾 (`interaction-manager.ts:174-207`)。
3. **不要把 `keepFullTurnCount` 当作完整 tool-history retention policy**：它只针对 Agent thought/action/observation turn；user messages/system events不按同一策略，heartbeat也未纳入 turn 判定 (`context-builder.ts:123-151`)。
4. **不要把 L2 邻居合并叫作 LLM compression**：它是 embedding retrieval + cosine + string line split/merge；真正 chat-model compression 只在 L3 diary (`l2-semantic-memory.ts:120-269`; `l3-archival-memory.ts:100-135`)。
5. **不要把 Members 表称为已接入的 user profile memory**：它被写入但不被 ContextBuilder 读取；L2 `participantIds` 也只是 chunk metadata (`event-listener.ts:327-345`; `context-builder.ts:63-99`; `l2-semantic-memory.ts:77-91`)。
6. **不要从 v3 推断 prompt-cache 命中率或 provider 价格优势**：没有 cache breakpoint、cache telemetry 或 provider-specific options；只能提出 [代码推断] 的布局假设，实际数据必须外部验证 (`chat-model.ts:107-172`)。
7. **不要把 `StimulusType` 的 scheduled/background union 当成已经实现的 rhythm/continuation runtime**：当前生产入口主要是 user message 和少量 system event；scheduler 只做 channel debounce/serialization (`types.ts:285-304`; `event-listener.ts:64-84`; `agent/scheduler.ts:30-79`)。
